# CUADC 虚拟云台增稳

当前实现面向 `CUADC2026` / `copter_rescue` 的固定下视 Gazebo 相机。
复用 CUADC Virtual Nadir 的纯旋转重投影方法，按本程序 ENU/FLU 坐标、
已锁定模型和现有遥测链重新实现，不导入旧项目 Python、UDP 接收器或 MAVLink 后端。

## 使用与作用域

重启控制中心及救援仿真实例，进入“车辆控制”，选择该实例，在“画面来源”中选择：

- **原始摄像头画面 · gimbal-camera**：真实相机原图。
- **增稳画面**：补偿横滚、俯仰并锁定启动时航向的虚拟下视图。
- **YOLO 识别画面（增稳）**：同一增稳帧上的 PT 桶检测与独立 H 标记检测。

查看不需要 SEND。切换来源只改变预览，不切换 Mission 的感知输入。
救援识别固定使用增稳域，目标定位也使用对应虚拟相机几何。
增稳随原车辆实例启动和退出，复用同一个相机及 PT 工作进程。
本阶段没有新增 `CameraStabilize` Action，也没有实体云台控制或手动航向重置。
需要任务分阶段管理时，可在该服务之上实现持续 Action 和共享使用关系。

## 数据和几何

`world/sensors/camera/motion.py` 保留已有合格遥测中的位置与姿态源捕获时刻，
分别形成最多 128 项、1.5 秒历史。重复发布不会生成新样本或提高报告频率。
`app/bootstrap/rescue_runtime.py` 只转交本实例的归一化遥测历史，不增加订阅连接、
飞控消息请求或写入通路。

图像保留原 Gazebo capture 和 receive 时间。主机捕获时间使用真实世界时钟历史中，
仿真时刻不晚于曝光、主机时刻不晚于原始接收的最近因果下界；时钟样本与曝光的
仿真间距最多 100 ms，与原始接收的主机间距最多 500 ms。没有合格样本就拒绝，
不假定仿真严格 1 倍速，也不用接收时刻替代曝光。匹配要求真实源样本夹住该下界，
位置线性插值、姿态四元数 SLERP，不外推；World generation、link session 和 clock
domain 固定。源时间回退或会话变化要求新的自有传感器实例。
底层只读 `MotionTelemetryHistory` 保留同次接收批次中的所有已准入样本，
不会把一次批量接收压成一个最新值。现有 TIMESYNC 遥测时间是保守的因果下界，
这里使用这些原有时间事实做有界近似，不宣称相机曝光与 IMU 已做精确物理同步，
也不改变原 source clock、签名或车辆控制的时间准入规则。

本模型原有 ATTITUDE/LOCAL_POSITION 为 10 Hz。2026-11-06 起只对救援仿真增加
`copter_rescue_vision.parm`，配置 ATTITUDE 30 Hz、LOCAL_POSITION 20 Hz，并在启动
时校验回读值，其他车辆配置不变。同步准入仍使用最低姿态频率 8 Hz、
单边距离最多 125 ms、插值区间最多 150 ms；这不是旧实机配置 25 Hz 门槛的移植，
也不能据此宣称快速实机运动增稳已经验证。历史发布与入站图像最多 500 ms，
推理原始捕获年龄最多 1 秒；所有派生画面保留原 sequence、capture 与 receive 时间。

`world/sensors/camera/virtual_nadir.py` 使用当前 SHA 锁定相机的 640×480、
水平 FOV 2 rad、方形像素、零畸变和固定安装变换，标定标识为
`cuadc2026-fixed-down-v1`。真实相机右/下/前轴在 FLU 中分别为 -Y/-X/-Z。
参考航向取第一帧合格姿态，输出旋转保持垂直下视和该航向。
重投影为 `K_virtual × R_virtualᵀ × R_real × K_real⁻¹`。

同一个自有 PT 进程内，独立线程在模型加载前启动增稳输出，不等待 YOLO 或位置。
待姿态原图最多 8 帧、原始捕获年龄最多 400 ms；等到真实后样本后再处理，不以
最新原图覆盖正在等待的原图。推理队列最多 4 帧，满时丢最旧推理输入而不阻塞
新画面。仅有姿态的画面明确 `position_valid=false`、`origin_enu=null`，不能定位。
位置或 YOLO 暂时失效会使控制观测 INVALID，但不使仍然新鲜的增稳画面失效。

定位额外要求合格位置插值，保留随真实机体旋转后的相机光心偏移，像素射线仅使用虚拟相机旋转，
不再次施加真实横滚/俯仰；桶口与地面的既有高度约定不变。
结果采用 schema 2，显式绑定图像域、标定标识和参考 ID。

## 失效与边界

大于约 60° 的光轴倾斜、有效视野不足 35%、过宽插值区间、姿态频率不足、
源过期或来源不匹配会停止采用检测。检测框中心必须在真实像素内，框内至少 95%
为有效区域，不能把黑边当作观测。待下一条真实样本的短暂等待不会作姿态外推。

同步失效会使现有视觉观测 INVALID，保留其原捕获时间，清除已知投放观测记录；
目标关联只保留最多 5 秒的身份候选，覆盖现有 1 秒观测 TTL 与 3 秒找回窗口，
不延长这两个控制时限，不能发布旧观测。恢复后必须用新检测、新投影
在 0.5 米内同类别/来源唯一匹配，重复或歧义框不继承原 ID，也不进入关联候选；
候选过期产生新 ID。
原对准 Action 的丢失目标退出与
投放最终安全栅栏继续生效，不用旧帧、旧姿态或旧目标补成功。
姿态同步或相机源失效后，增稳画面只在其原捕获年龄仍合格时可查看，过期后标记
不可用；旧截图拒绝。位置和推理独立失效时，仍可查看姿态合格的增稳画面。

图像变换不能补回原视野之外的内容、消除曝光运动模糊或稳定车辆平移。
这里没有新增实机相机标定、实体云台、RKNN、ROS 或硬件 SEND 支持。
摄像头关闭、推理进程清理和 UNCONFIRMED 语义仍归原 Owner。

## 验证入口

```bash
python -m unittest discover -s tests -v
python -m tests.simulation.yolo_preview artifacts/new-nadir-preview
python -m tests.simulation.rescue_2026 artifacts/new-nadir-rescue --flight
python -m tests.simulation.rescue_2026 artifacts/new-nadir-recording --flight --record-camera-comparison
```

最后一个入口仅对新建的自有 loopback 仿真授权任务 SEND。
单元测试验证组合倾斜/转向时原始与虚拟像素射线的世界交点一致、航向跨 ±π 插值、
原图不变、有效区域、源时钟/会话及失效清理。实际原生结果独立记录，不能用这些
软件几何夹具代替飞行验收。

显式 `--record-camera-comparison` 在完整任务开始前启动只读观察器，保存原始 JPEG、
实际发布的增稳 JPEG、原捕获时间、任务阶段及逐帧索引。两侧必须具有相同 source、
sequence、capture clock、capture ns 和原始 receive ns；不匹配会使录制失败。
观察器只关闭自己的线程和文件，不启动推理、不改变感知输入，也不关闭车辆相机。
2026-11-06 起使用生产端最多 64 槽的原图/增稳配对历史恢复短暂发布突发；
每帧仍须在原始捕获一秒内、同一存活 Owner/模型/参考/World 下读取。此历史仅用于
显式录制导出，不用于控制或旧帧播放。补录可能让原图索引的写入顺序不同于捕获
顺序，离线视频必须按原 `captured_ns` 排序。
导出位于该次测试目录的 `camera-comparison/`，不作为正常启动的软件输入。
视频可在仿真结束后离线合成，避免编码负载影响控制；缺少增稳输出的原帧须明确
标为不可用，不能用旧增稳图像冒充。这是同次飞行的处理前后对比，不是两次独立
开关增稳后的任务成功率比较。

2026-11-05 完整录制位于 `artifacts/rescue-video-comparison-20261105-r1/`：
35 个 Action 全部成功，原始 3395 帧、严格同帧配对的增稳输出 2920 帧，
录制无错误，自有仿真清理 COMPLETE。导出的 `rescue-nadir-comparison-full.mp4`

无合格增稳输出的时刻明确标注，背景仅显示变暗的同帧原图，不用旧增稳帧补齐。
