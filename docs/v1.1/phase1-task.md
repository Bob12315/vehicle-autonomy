## 三、开发范围

### 1. MAVLink 通信系统

检查并完善现有 MAVLink 实现，包括：

- MAVLink 2 消息接收与解析。
- 命令编码和发送。
- 心跳检测。
- 飞控 System ID / Component ID / 车型识别。
- 连接状态与通信健康。
- 断开、超时、重连。
- 飞控重启后的会话隔离。
- 命令 ACK 与结果状态。
- 重复、过期、异常消息处理。

优先复用现有 `pymavlink`、MAVLink Codec、Session 和命令端口。

不得为了重构而重新实现一套已经正确工作的 MAVLink 协议栈。

接收与发送逻辑应保持独立：

**即使未授予 SEND 权限，也必须能够正常接收和查询遥测。**

### 2. 统一 VehicleState

统一 ArduRover 与 ArduCopter 的基础遥测状态，至少检查以下信息：

- Heartbeat、连接与会话信息。
- 车辆类型、飞控模式、Arm/Disarm 状态。
- ATTITUDE 及相关姿态数据。
- GLOBAL_POSITION_INT。
- LOCAL_POSITION_NED。
- GPS_RAW_INT。
- 可用的 EKF 状态。
- 电池和供电信息。
- COMMAND_ACK。
- STATUSTEXT 等告警。

具体消息按当前 ArduPilot SITL 实际支持情况处理，不要求实现全部 MAVLink 消息。

必须保证：

1. 正确区分原始 MAVLink 数据和标准化 VehicleState。
2. NED/FRD 与 ENU/FLU 的转换符合现有合同。
3. 保留数据来源、时间、坐标系、质量、新鲜度与会话信息。
4. 对未收到、过期或无效的数据显式报告状态，不得伪造有效数值。
5. 不因收到新消息就假定其中的传感器采样时间也是新的。
6. 重新连接后，旧会话数据不能污染新会话状态。

本阶段只处理来自 AP 的车辆遥测，不开发机载电脑直连的 Camera/LiDAR 采集链。

### 3. 基础车辆命令

检查并完善统一车辆命令接口：

- SetMode
- Arm
- Disarm
- 位置目标命令合同
- 速度目标命令合同
- Stop / Cancel
- 命令状态与失败反馈

必须根据车辆能力判断命令是否适用。

Rover 和 Copter 的命令翻译器应分别处理车型差异，不得假定两个车型具有完全相同的控制语义。

对于阶段 1，允许使用有限、安全的 SITL 基础运动命令证明实际执行链闭环，但不必完成阶段 2 的全部运动场景。

对于 Plane，只检查车型扩展边界，不实现专属起降与航线功能。

### 4. Execution、Authority 与 Safety

保留并完善现有安全机制：

- System SEND。
- Action SEND。
- Control Lease。
- 会话与命令身份。
- 命令时效。
- 状态新鲜度检查。
- 车型能力校验。
- 安全策略。
- 唯一 MAVLink Writer。
- Stop / Cancel 结果反馈。

默认必须禁止发送车辆运动指令。

测试中的发送权限只能在明确创建、隔离并确认的本地 SITL 会话中开启。

必须明确区分：

- Command submitted
- Command transmitted
- ACK received
- Vehicle state confirmed
- Physical outcome confirmed
- Failed / Timed out / Unconfirmed

特别注意：ACK 不等于运动完成，Cancel 被接受不等于车辆已经停止。

不得通过降低安全阈值、跳过 Safety 或关闭控制权检查来解决测试失败。

## 四、真实仿真开发与验收

当前电脑已经安装 Gazebo 和 ArduPilot SITL。

请主动检查已有环境、ArduPilot 源码、Gazebo 版本、插件、车辆模型、运行脚本和相关配置。

优先使用已存在、曾通过验收的 Rover/Copter SITL + Gazebo 运行环境。

**本阶段必须实际运行 SITL 和 Gazebo，不能只运行 Mock 测试。**

### 六组强制验收

**A. 连接与车型识别**

实际启动 Rover/Copter SITL + Gazebo。

验证：

- 成功建立通信。
- 接收真实 Heartbeat。
- 正确识别车辆类型和会话。
- 持续发布连接状态。

**B. MAVLink 遥测**

检查真实姿态、位置、速度、飞控模式等数据。

验证：

- 原始数据成功解析。
- 标准 VehicleState 正确。
- 坐标转换正确。
- 数据过期能被检测。
- 对可取得的状态，使用 Gazebo 物理真值进行独立比对。
- 不可用的消息被如实标记。

**C. 基础指令闭环**

通过正式 Execution 链发送限定的 SITL 控制指令。

验证：

- 命令经过正确的车型翻译器。
- 正确生成 MAVLink。
- 得到实际 ACK 或明确的协议结果。
- 对需要确认的命令验证飞控后续状态。
- 对运动命令验证相应 Gazebo 物理状态。

不得使用直接发送 MAVLink 的测试捷径代替正式链路验收。

**D. 授权与安全**

验证以下请求不会产生未经授权的车辆写入：

- 默认 SEND 关闭。
- 无效或缺失 Lease。
- 过期命令。
- 过期状态。
- 非法坐标系。
- 不支持的车型能力。
- 错误会话命令。

使用可观察的 Writer 或链路证据验证拒绝结果。

**E. 故障与恢复**

测试：

- MAVLink 链路中断。
- Heartbeat 超时。
- SITL 重启。
- 会话变化。
- 重复或过期消息。
- 延迟 ACK。
- 取消与停止结果不确定。

必须证明旧会话的命令不能在重新连接后自动重放。

当无法确认物理停止时，必须报告 UNCONFIRMED 或等价故障状态，不能伪报成功。

**F. 稳定性与重复性**

检查：

- 持续遥测接收。
- 多次连接与关闭。
- 重复运行。
- 线程、进程、Socket 和端口清理。
- 无明显资源泄漏或旧状态污染。

强制验收测试至少完成两次独立运行。

每次使用独立运行标识、独立测试报告和可追溯证据。
