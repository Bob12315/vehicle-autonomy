# P0 inventory: foundation contract migration candidates

Status: P0 scoped audit complete on 2026-09-30. This inventory records the archived implementation under `legacy/cuadc_2026/` against the frozen target in [foundation_contracts_v1.md](../foundation_contracts_v1.md). A decision describes migration suitability, not permission to copy code. No implementation was changed or migrated.

## 1. Scope

The completion claim covers `contracts/`, state/frame/time code in `telemetry_link/`, dependent `application/core/` modules, and related tests. Adjacent Execution and direct command-writer paths were inspected for safety implications, not approved for migration. No full audit of Web, competition Mission logic, YOLO, Gazebo, or deployment was attempted. The focused test commands and results are in [p0_baseline.md](p0_baseline.md).

## 3. MIGRATE candidates

- `SchemaVersion`
- `ResourceVersion`
- `FrozenJson` / canonical immutable JSON helper
- Selected plain identity aliases after separating execution authorization/generation identity

These are the strongest low-dependency candidates. Keep their existing invariants and serialization tests when package boundaries move.

## 4. ADAPT candidates

- `CoreTime` / `ClockStamp` and explicit captured/received/published timestamps
- Geometry values and VehicleState, including the MAVLink-to-Core coordinate boundary
- Vehicle-state adapter, cache publication and perception/observation contracts
- WorldSnapshot and typed request-only Effect
- VehicleCommandEnvelope plus state/command ports
- Execution submission interfaces, in a later phase than base types

For P1, focus on contract values and their invariants. Do not migrate the operational adapters, execution pipeline, Mission, or Action implementation as part of P1 base-contract work.

## 5. KEEP candidates

- Legacy telemetry receiver/cache and application compatibility projections until all old consumers have moved
- Legacy UDP state publisher and diagnostic support while needed operationally
- Current domain localization/fusion and application-specific contracts until an independent generic Localization producer/consumer requirement is evidenced
- `application/core` runtime, input collector and stores while the archived application depends on them
- Legacy contracts/DTOs needed by the still-running archived tree

KEEP means retain only for migration continuity. It does not endorse these as final foundation contracts.

## 6. DROP candidates

- Old competition FIELD coordinate abstraction from the new base contracts
- MAVLink frame integer constants and NED/FRD protocol semantics in Core
- `source = real / sitl / test` as a base VehicleState semantic
- `Mapping[str, Any]` or mapping-shaped Effect as the stable typed Effect API
- VehicleCommandPort methods that let upper layers call `local_position()`, `takeoff()`, `set_servo()`, or equivalent directly
- Legacy `RuntimeSnapshot` when it is an aggregate of dict/DTO compatibility views

DROP marks migration destination only. Nothing was removed in P0.

## 7. Dependencies requiring special attention

- `pymavlink`, MAVLink frame values, NED/FRD field order, local/global targets and Euler angles currently meet state and command code near the `vehicles/multirotor` and `telemetry_link` boundary. Keep all of them out of Core.
- `source`, link-session IDs, `control_allowed`, SEND flags, authorization, leases and generations are present in legacy platform/runtime values. Decide ownership field-by-field; VehicleState must not inherit command authorization.
- State snapshots contain dynamic `*_age_s` alongside receive timestamps. Keep captured, received and published timestamps as facts; compute age using an identified clock domain.
- Legacy Field `ReferenceVersion` is attached to local/global command/effect targets. Its future mapping to generic `frame_id` and world-resource provenance needs deliberate adaptation; do not migrate competition FIELD itself.
- Generic `infrastructure/transports/{serial,udp}.py` have raw write methods, but their active production command composition is UNKNOWN in this scope. Do not connect them in P1.
- `telemetry_link/config.py` selects exactly one of the old queue writer and typed broker writer; the debug tool can submit to the old one with `--allow-send` without passing Execution.

## 8. Candidates for P1 基础合同迁移

1. Establish `SchemaVersion`, `ResourceVersion`, selected ID aliases, and `FrozenJson` in the new contract package with their current invariant tests.
2. Establish the unified time values and facts (`monotonic_ns`, UTC, `clock_domain_id`; captured/received/published) before adapting any state DTO.
3. Establish frame-aware SI geometry and the reported `VehicleState` contract, with tests proving MAVLink NED/FRD conversion remains at the adapter boundary and state does not imply SEND permission.

Then define the first `Observation`, independent `LocalizationEstimate`, `WorldSnapshot` provenance fields, Typed Effect, and narrow VehicleCommand/ports against the frozen specification. Keep the P1 scope at the contract layer; state-chain adapters, Execution behavior and command transport are subsequent stages.
