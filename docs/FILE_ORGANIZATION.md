# 文件组织与运行环境规范

本规范落实 2026-10-30 用户确认的整理要求，补充而不替代根目录 V1.0 行为基线和
V1.1 七模块归属基线。文件整理不扩大 SEND、硬件控制或任何未验收能力。

## 程序、资源与外部软件

`src/vehicle_autonomy/` 是唯一正式源码根，保留 contracts、engine、actions、
vehicles、world、autonomy、app 七模块。前端和框架维护的 C++/ROS 桥接同样属于源码。
薄命令入口可以位于 scripts 或 simulation/world_registry；实现代码应在 src，
显式开发和测试工具不成为正式运行依赖。

contracts 定义类型与端口；engine 管理执行、资源、授权和安全；actions 实现可编排
能力；vehicles 负责车型、会话、协议与传输；world 生产观测、定位、地图和世界状态；
autonomy 提供规划、引导和智能提案；app 提供用例、界面、入口和装配。

Gazebo、ArduPilot、QGC、ROS 2、RViz2、第三方 SDK、完整上游软件源码与安装包
位于仓库外。`environments/` 只保存索引和配置模板。本机索引不提交、不打入 wheel。
软件版本和关键文件指纹应保留，不能为了改路径而放宽既有锁定清单。

`configs/` 保存业务、车辆、安全与显示配置；`simulation/` 保存自有模型、场景、
任务、参数以及来源/版本/许可证/校验索引。第三方大型下载和构建产物存于外部目录。
原生派生代码及其许可证、上游声明必须保留，不能误当整套第三方软件删除。

## 统一路径与入口

HostEnvironment 统一选择本机索引和查找软件。显式参数优先于 VAF 环境覆盖，
环境覆盖优先于本机索引，最后才使用受控发现。显式配置错误时不替换为另一套软件。
模板不参与实际软件路径发现；普通启动不自动下载软件。

版本化资源由 `_resources.resource_root` 定位，源码安装和 wheel 均不依赖当前目录。
可写位置由 RuntimePaths 定位；安装包资源目录不承担持久状态存储。
现有软件初始化脚本只在明确启动的子进程中执行，基础包和单元测试不强制加载 ROS。

正式程序通过安装后的 CLI 或 `python -m vehicle_autonomy...` 运行。薄 Shell 入口
使用项目 .venv 或显式 VAF_PYTHON；不会通过旧包镜像或临时 PYTHONPATH 找到业务代码。

## 状态与生成数据

- `runtime/state/`：认证配置、任务持久状态、工具配置及共享所有权锁。
- `runtime/sessions/`：每次启动的独立会话、进程归属和会话日志。
- `runtime/logs/`：日常日志；Web 审计保留原有大小与备份轮转约束。
- `runtime/cache/`：可以重新生成的数据，不能包含唯一的用户状态。
- `artifacts/`：测试、验收、导出结果，不能作为正常启动的软件来源。

持久状态与执行恢复日志不批量清空。历史验收记录允许显式归档，保留原始内容及
迁移索引；对会话执行归档前必须确认没有活跃所有者。不会通过旧 PID 或旧会话恢复 SEND。

## 迁移与验证

先建立索引，再切换入口并验证，最后移出不再被正常路径引用的软件副本。
外部既有独立工程只作为输入，不修改其源码。保留双 SEND、SafetyPolicy、Lease、TTL、
会话/代际围栏、唯一 MAVLink writer、UNCONFIRMED 停止和硬件 receive-only 限制。

每阶段完成单元测试及相关仿真回归并提交；资源迁移还需检查 wheel、异目录启动、
本机软件查找、持久配置保留和原进程清理。不得删除必要测试来取得 PASS。
